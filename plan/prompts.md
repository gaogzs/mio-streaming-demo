# prompts 模块计划

## 模块职责

提供通用提示词加载功能，通过委托 PersonaLoader 获取角色信息，组装完整的系统提示词。

## 文件结构

```
prompts/
├── __init__.py           # 模块导出
├── prompt_loader.py      # PromptLoader类（委托 PersonaLoader）
├── base_instruction.txt  # 主播基础指令
├── studio/
│   ├── comment_headers.txt         # 弹幕区标题（key=value）
│   ├── interaction_instruction.txt # 互动目标指令
│   └── silence_notice.txt          # 沉默提示
├── topic/
│   ├── single_classify.txt         # 单条弹幕分类
│   ├── batch_classify.txt          # 批量弹幕分类
│   ├── content_analysis.txt        # 内容分析
│   ├── rhythm_analysis.txt         # 节奏分析
│   ├── stale_instruction.txt       # 过期话题指令
│   └── followup_instruction.txt    # 跟进建议指令
└── memory/
    ├── interaction_summary.txt     # 交互记忆总结
    └── periodic_summary.txt        # 定时汇总
```

## 核心类: PromptLoader

内部持有 PersonaLoader 实例，负责组装 base_instruction + 角色提示词。

### 方法

| 方法 | 说明 |
|------|------|
| `load(filename)` | 加载指定提示词文件 |
| `load_headers(filename)` | 加载 key=value 格式的 headers 文件 |
| `get_base_instruction()` | 获取基础指令 |
| `get_full_system_prompt(persona)` | 基础指令 + 角色提示词（委托 PersonaLoader） |
| `list_personas()` | 列出所有可用角色（委托 PersonaLoader） |

# Prompt 优化诊断与计划

## 当前问题诊断

### 问题现象

主播回复不够自然，发言连续性差，话题过渡生硬。

### 根因分析

#### 问题 1：LLM 不知道自己上次说了什么（最关键）

Studio 调用 `save_history=False`，LLM 的对话 history 始终为空。每次生成回复时，LLM 只有：
- System prompt（静态人设）
- 记忆摘要（经过小 LLM 总结的间接信息，有损失）
- 话题上下文（高层摘要）
- 当前弹幕批次

**结果**：LLM 每次都从零开始组织回复，无法承接上文，自然无法做到"连续对话"。

Active 层的 `original_response` 虽然保存了原回复，但只有 5 条容量，且格式为"（我当时说：...）"，
LLM 需要从记忆列表中推断上下文，远不如直接看到"你上一句话是这个"来得直接。

#### 问题 2：弹幕 prompt 格式过于结构化

当前格式：
```
- [话题: 游戏 | 优先回复] [14:23:05 / 35秒前] 花凛 (id: user_abc): 主播唱首歌
```

- `(id: user_abc)` 对 LLM 无用，增加噪音
- 绝对时间 `[14:23:05]` 在 base_instruction 中明确要求不使用具体时间，但又给出了
- 过多的方括号标签让 prompt 读起来像机器格式，可能影响 LLM 的"语感"

#### 问题 3：base_instruction 偏"规则约束"，缺"行为引导"

当前 base_instruction 以"不要做X"、"必须做Y"为主，缺乏：
- 如何自然地承接上文
- 如何从一个话题过渡到另一个
- 什么时候该展开话题，什么时候该收束
- 回复节奏的内在逻辑（为什么有时长有时短）

#### 问题 4：上下文注入顺序不够直觉

当前 `extra_context` 的组装顺序：
```
场景快照 → 记忆 → 话题上下文
---
弹幕
```

LLM 先读到大量背景（记忆、话题），最后才看到弹幕。
对于"回应观众"这个核心任务，弹幕应该是最显眼的，但它被推到了最后。

#### 问题 5：话题指令生硬

话题格式化中的指令如：
- `「唱歌话题」已经聊了很久，建议逐步转移话题。可以试试：聊点新歌吗？`

这类"第三方顾问"口吻的指令直接注入到 prompt，可能让 LLM 产生割裂感——
一边是扮演主播的人设，一边是接收"顾问建议"，角色不一致。

---

## 改进方案

### 方案 1：注入上一次回复（影响最大，最优先）

**做法**：在 user message 中显式注入主播的上一条完整回复。

**位置**：紧接在弹幕区之前，让 LLM 先看到"我上次说了什么"再看"观众怎么回应的"。

**格式**：
```
【你上次说的话】
#[smile][happy]哈哈，那个游戏确实很好玩！我最近在玩XX来着~
```

**实现**：
- `StreamingStudio` 保存 `_last_response_content: Optional[str]`
- 在 `_format_comments_for_prompt()` 开头注入
- 新增 prompt 模板 `prompts/studio/last_response.txt`

**注意**：这里注入的是完整原文，不是记忆摘要。让 LLM 直接看到自己上一轮的完整输出。

### 方案 2：精简弹幕格式

**做法**：去掉 `(id: xxx)` 和绝对时间，只保留相对时间和昵称。

**改前**：
```
- [话题: 游戏 | 优先回复] [14:23:05 / 35秒前] 花凛 (id: user_abc): 主播唱首歌
```

**改后**：
```
- [话题: 游戏 | 优先回复] [35秒前] 花凛: 主播唱首歌
```

**影响**：
- 减少 token 消耗
- 减少 LLM 的认知负担
- 更接近人类阅读弹幕的感觉

### 方案 3：重写 base_instruction — 从"规则"到"行为引导"

**核心思路**：把"不要做X"改成"像Y一样做"，通过描述理想行为来引导。

**新增内容**（在现有基础上补充）：

```
## 发言连续性

你在持续直播中，每次发言都是上一句话的延续。你刚才说过的话（会在【你上次说的话】中看到）
是你思考下一句的起点。

- 如果你刚才在讨论某个话题，优先延续或自然收束，而不是突然跳到完全无关的内容
- 如果有新弹幕提出了新话题，可以自然过渡："哦对了，说到这个..."、"诶 {昵称} 提到了..."
- 如果没有新弹幕，可以继续你上一句话的思路往下说，或者自然感慨

## 话题过渡

不要生硬地切换话题。好的过渡方式：
- 承接型："说到游戏，我想起来..."
- 回应型："欸 {昵称} 说得对，不过..."
- 收束型："嘛，{话题} 就先聊到这吧~"

## 回复节奏感

- 不是每条弹幕都需要单独回应，可以把几条相关的弹幕合在一起回应
- 有时候一两句轻松的感想比详细的回答更自然
- 回复长度取决于内容：简单问候一句话，有深度的话题可以多说几句
```

### 方案 4：调整上下文注入顺序

**改前**（current）：
```
场景快照
记忆
话题上下文
---
弹幕
```

**改后**（proposed）：
```
场景快照
你上次说的话
---
弹幕 + 话题标注
---
记忆
话题指令
```

**逻辑**：
1. 场景快照：让 LLM 知道"我在哪"
2. 上次回复：让 LLM 知道"我刚说了什么"
3. 弹幕：让 LLM 知道"观众在说什么"（核心输入）
4. 记忆+话题指令：补充背景和行为建议（辅助信息）

**核心原则**："主线信息"（上次发言 → 弹幕 → 回复）在前面，"辅助信息"在后面。

### 方案 5：话题指令口吻调整

**改前**（第三方顾问口吻）：
```
【话题指令】
- 「唱歌话题」已经聊了很久，建议逐步转移话题。可以试试：聊点新歌吗？
```

**改后**（主播内心提示口吻）：
```
【直觉提醒】
- 「唱歌」这个话题已经聊了一会儿了，可以自然地收束一下
- 「游戏讨论」正在升温，观众很感兴趣
```

减少"建议""应该"等顾问措辞，改用更贴近内心感觉的表达，
让 LLM 感觉是自己的直觉在提示，而不是外部指令在控制。

### 方案 6（可选/延后）：轻量对话历史

**现状**：`save_history=False`，history 始终为空。

**问题**：方案 1 虽然注入了上一条回复，但 LLM 仍然没有 multi-turn 的上下文。
长时间直播后，LLM 无法感知"我今天聊了什么"——只能通过记忆系统的摘要。

**可选方案**：保存最近 2-3 轮的精简历史（而非完整 prompt）

```python
# 不保存 full user_input（含 20 条弹幕的长 prompt）
# 只保存 "精简版"
condensed_input = f"[直播弹幕互动] 新弹幕 {len(new_comments)} 条"
self._history.append((condensed_input, response.content))
```

但这可能引入 token 成本和复杂度，**暂时延后**。方案 1 的"上次回复"注入足以解决最急迫的连续性问题。

## 优先级排序

| 优先级 | 方案 | 影响面 | 实现难度 |
|--------|------|--------|----------|
| P0 | 方案 1：注入上一次回复 | 连续性核心改善 | 低 |
| P1 | 方案 2：精简弹幕格式 | 减少噪音、省 token | 低 |
| P1 | 方案 3：重写 base_instruction | 行为引导 | 中（纯文案） |
| P2 | 方案 4：调整上下文顺序 | 信息层次更清晰 | 低 |
| P2 | 方案 5：话题指令口吻 | 减少割裂感 | 低（纯文案） |
| P3 | 方案 6：轻量对话历史 | 深层上下文 | 中（需测试） |
